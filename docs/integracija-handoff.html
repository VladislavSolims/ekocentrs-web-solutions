Īsumā

  1. Anketa tiek izvietota uz anketa.ekocentrs.lv jūsu serverī.

Divas lapas ar pretējām prasībām

Šī ir vienīgā vieta, kur kaut ko var viegli sajaukt, tāpēc tā ir pašā sākumā. Lietotnē ir divas lapas, un tām vajag tieši pretējo.

Klients kontu nesaņem un nesaņems. Aģents izveido saiti un nosūta to klientam, piemēram, WhatsApp. Visi darījuma dati ir iekodēti pašā saitē, tāpēc saitei jāatveras uzreiz, bez pieteikšanās.

Ieviešanas soļi

Lietotnes izvietošana jūsu serverī

Kas nepieciešams: Node.js 20+, git un aptuveni 1 GB brīvas RAM (sk. piezīmi zemāk).

Pirmkods ir privātā Git repozitorijā. Ērtākais veids, kā to dabūt uz servera — uz paša servera uzģenerējiet atslēgu un atsūtiet mums publisko daļu (.pub faila saturs, to var sūtīt parastā e-pastā): 

ssh-keygen -t ed25519 -C "anketa-deploy" -f ~/.ssh/anketa_deploy
cat ~/.ssh/anketa_deploy.pub

Mēs to pievienosim repozitorijam kā deploy key tikai lasīšanai — tālāk git clone un vēlāk git pull atjauninājumiem. Privātā atslēga nekad neatstāj jūsu serveri. Ja jums ērtāk vienkārši arhīvs — pasakiet, atsūtīsim.

Kad būsim atslēgu pievienojuši, atrakstīsim, un kodu var paņemt:

git clone git@github.com:VladislavSolims/ekocentrs-web-solutions.git anketa
cd anketa
# vēlāk atjauninājumiem pietiek ar:
git pull
npm ci
npm run build
npm start          # ports 3000

Viens vides mainīgais

Projekta saknē izveidojiet .env.local ar vienu rindu: 

AGENT_LOGIN=external

Tas nozīmē: par piekļuvi rūpējas kaut kas lietotnes priekšā (4. solis), un pati lietotne pieteikšanos neprasa. Noklusējuma vērtības nav ar nodomu — ja mainīgais nav uzstādīts, lietotne atsakās atdot /izveidot lapu, nevis klusi atver to visiem.

Saite Joomla izvēlnē

Joomla admin → Izvēlne → Jauns elements → tips Ārēja URL: 

URL:              https://anketa.ekocentrs.lv/izveidot
Piekļuves līmenis: Special (vai jūsu aģentu līmenis)

Piekļuves līmenis tikai paslēpj saiti no citiem vietnes apmeklētājiem — īsto ierobežojumu uzliek 4. solis.

Bez iframe. Aģentu lapu nevajag iebūvēt rakstā kā <iframe>: daļa pārlūku bloķē trešās puses sīkdatnes, un lapa uzvedīsies neparedzami. Klienta anketai iframe arī neder — visi darījuma dati ir saites parametrā, un iframe iekšpusē tie nenonāk.

Piekļuves ierobežojums /izveidot lapai

Šo mēs atstājam jūsu ziņā — jūs vislabāk zināt, kas jau darbojas jūsu infrastruktūrā. Lietotnes pusē neko konfigurēt nevajag: tā ir gatava strādāt aiz jebkāda ārēja ierobežojuma un pati pieteikšanos neprasa.

Trīs izplatītas iespējas, ja noder:

  • Cloudflare Access — bezmaksas līdz 50 lietotājiem, pieteikšanās ar Google kontu, ierobežojumu var likt uz konkrētu ceļu.
  • IP whitelist uz biroja tīklu — vienkāršākais, bet aģents nevar strādāt no mājām vai no telefona.
  • HTTP Basic Auth uz location /izveidot — viena parole visiem aģentiem, uzstādāma nginx konfigurācijā divās rindās.

Ja jums ērtāk kaut kas cits — dariet, kā uzskatāt par pareizu. Vienīgais nosacījums ir tas, kas aprakstīts lapas sākumā: ierobežojums attiecas tikai uz /izveidot, un /aizpildit paliek publisks.

Pārbaude

  • Aģents no biroja atver izvēlnes saiti → nokļūst saišu izveides lapā.
  • Nepiederoša persona atver anketa.ekocentrs.lv/izveidot → netiek iekšā.
  • Klienta saite /aizpildit?d=… atveras anonīmi — citā pārlūkā, telefonā, bez VPN un bez konta.
  • Klients aizpilda anketu līdz galam un lejupielādē PDF.

Kad esat pabeidzis

Mums vajag trīs lietas:

  • publiskā deploy atslēga no 1. soļa (vai ziņa, ka vēlaties arhīvu);
  • apstiprinājums, ka anketa.ekocentrs.lv ir izveidots un norāda uz pareizo vietu;
  • īss apraksts, kā tieši /izveidot ir aizsargāts — lai mēs zinātu, ko teikt aģentam, kad viņš pirmoreiz mēģinās ieiet.

Ja rodas jautājumi vai kaut kas jūsu infrastruktūrā prasa citu pieeju — rakstiet, pielāgosimies.

Подключение анкеты к сайту ekocentrs.lv

AML/KYC анкета идентификации клиента — это самостоятельное приложение на Next.js. Оно не устанавливается внутрь Joomla и не требует изменений в коде сайта: работает на своём поддомене, а с сайта на него ведёт обычная ссылка.

Коротко

  1. Приложение размещается на anketa.ekocentrs.lv на вашем сервере.
  2. В меню Joomla появляется ссылка на него.
  3. Одну страницу — /izveidot — нужно закрыть от посторонних так, как вам удобнее. Остальное остаётся публичным.

Две страницы с противоположными требованиями

Это единственное место, где легко ошибиться, поэтому оно в самом начале. В приложении две страницы, и им нужно прямо противоположное.

У клиента нет и не будет учётной записи. Агент создаёт ссылку и отправляет её клиенту, например через WhatsApp. Все данные сделки закодированы в самой ссылке, поэтому она должна открываться сразу, без входа.

Шаги внедрения

Размещение приложения на вашем сервере

Что нужно: Node.js 20+, git и около 1 ГБ свободной памяти (см. примечание ниже).

Исходный код лежит в приватном Git-репозитории. Самый удобный способ получить его на сервер — сгенерировать ключ прямо на сервере и прислать нам публичную часть (содержимое файла .pub, её можно слать обычной почтой): 

ssh-keygen -t ed25519 -C "anketa-deploy" -f ~/.ssh/anketa_deploy
cat ~/.ssh/anketa_deploy.pub

Мы добавим её к репозиторию как deploy key только на чтение — дальше git clone, а для обновлений git pull. Приватный ключ при этом никогда не покидает ваш сервер. Если удобнее просто архив — скажите, пришлём.

Как только добавим ключ, мы вам ответим, и код забирается так:

git clone git@github.com:VladislavSolims/ekocentrs-web-solutions.git anketa
cd anketa
# в дальнейшем для обновлений достаточно:
git pull
npm ci
npm run build
npm start          # порт 3000

В корне проекта создайте .env.local с одной строкой: 

AGENT_LOGIN=external

Уровень доступа лишь прячет ссылку от остальных посетителей сайта — настоящее ограничение ставится в шаге 4.

Без iframe. Страницу агентов не стоит встраивать в статью через <iframe>: часть браузеров блокирует сторонние cookie, и страница будет вести себя непредсказуемо. Для анкеты клиента iframe тоже не подходит — все данные сделки лежат в параметре ссылки, а внутрь iframe они не попадают.

Ограничение доступа к /izveidot

Это мы оставляем на ваше усмотрение — вы лучше знаете, что уже работает в вашей инфраструктуре. На стороне приложения настраивать ничего не нужно: оно готово работать за любым внешним ограничением и само входа не требует.

Три распространённых варианта, если пригодятся:

  • Cloudflare Access — бесплатно до 50 пользователей, вход через Google-аккаунт, ограничение можно повесить на конкретный путь.
  • Список IP-адресов офиса — самое простое, но агент не сможет работать из дома или с телефона.
  • HTTP Basic Auth на location /izveidot — один пароль на всех агентов, ставится в конфиге nginx в две строки.

Если вам удобнее что-то другое — делайте так, как считаете правильным. Единственное условие — то, что описано в начале страницы: ограничение касается только /izveidot, а /aizpildit остаётся публичным.

Проверка

  • Агент из офиса открывает ссылку в меню → попадает на страницу создания ссылок.
  • Посторонний открывает anketa.ekocentrs.lv/izveidot → не попадает внутрь.
  • Ссылка клиента /aizpildit?d=… открывается анонимно — в другом браузере, на телефоне, без VPN и без учётной записи.
  • Клиент заполняет анкету до конца и скачивает PDF.

Когда закончите

Нам нужны три вещи:

  • публичный deploy-ключ из шага 1 (или сообщение, что предпочитаете архив);
  • подтверждение, что anketa.ekocentrs.lv создан и указывает куда нужно;
  • короткое описание, чем именно защищён /izveidot — чтобы мы знали, что сказать агенту, когда он в первый раз попробует зайти.

Если возникнут вопросы или что-то в вашей инфраструктуре требует другого подхода — напишите, подстроимся.

Connecting the questionnaire to ekocentrs.lv

The AML/KYC client identification questionnaire is a standalone Next.js application. It is not installed inside Joomla and needs no changes to the site's code: it runs on its own subdomain, and an ordinary link leads to it from the site.

Site
Joomla 3.10.10
Application
Next.js 16 / Node
Subdomain
anketa.ekocentrs.lv
Changes to Joomla code
none

In short

  1. The application is deployed to anketa.ekocentrs.lv on your server.
  2. A link to it appears in the Joomla menu.
  3. One page — /izveidot — needs to be closed off, however suits you best. Everything else stays public.

Two pages with opposite requirements

This is the one place that is easy to get wrong, which is why it comes first. The application has two pages, and they need the exact opposite of each other.

The client has no account and never will. An agent creates a link and sends it to the client, over WhatsApp for instance. All the transaction details are encoded in the link itself, so it has to open straight away, with no sign-in.

Implementation steps

Deploying the application on your server

What it needs: Node.js 20+, git, and around 1 GB of free RAM (see the note below).

The source lives in a private Git repository. The easiest way to get it onto the server is to generate a key on the server itself and send us the public half (the contents of the .pub file — safe to send by ordinary email): 

ssh-keygen -t ed25519 -C "anketa-deploy" -f ~/.ssh/anketa_deploy
cat ~/.ssh/anketa_deploy.pub

We will add it to the repository as a read-only deploy key — then git clone, and git pull for later updates. The private key never leaves your server. If an archive is simpler for you, just say so.

Once we have added the key we will write back, and the code is fetched with:

git clone git@github.com:VladislavSolims/ekocentrs-web-solutions.git anketa
cd anketa
# later updates need only:
git pull
npm ci
npm run build
npm start          # port 3000

One environment variable

Create .env.local in the project root with a single line: 

AGENT_LOGIN=external

This says: access is handled by whatever sits in front of the application (step 4), and the application asks for no sign-in of its own. There is deliberately no default — with the variable unset the application refuses to serve /izveidot rather than quietly opening it to everyone.

If the PDF fails to generate, this is where to look — the rest of the application runs without them.

DNS record

A TLS certificate is required.

Link in the Joomla menu

Joomla admin → Menus → Add New Menu Item → type External URL: 

URL:           https://anketa.ekocentrs.lv/izveidot
Access level:  Special (or your agents' level)

The access level only hides the link from other visitors — the real restriction is step 4.

No iframe. The agent page should not be embedded in an article as an <iframe>: some browsers block third-party cookies and the page will behave unpredictably. An iframe does not suit the client questionnaire either — all the transaction details live in the link's parameter, and they never reach the inside of an iframe.

Access restriction on /izveidot

We leave this to you — you know best what already works in your infrastructure. Nothing needs configuring on the application's side: it is built to sit behind any external restriction and asks for no sign-in of its own.

Three common options, in case they help:

  • Cloudflare Access — free for up to 50 users, sign-in with a Google account, and the restriction can be placed on a specific path.
  • IP allowlist for the office network — the simplest, but an agent cannot then work from home or from a phone.
  • HTTP Basic Auth on location /izveidot — one password for all agents, two lines in the nginx config.

If something else suits you better, do it the way you think is right. The only condition is the one described at the top of this page: the restriction applies to /izveidot only, and /aizpildit stays public.

Checking it works

  • An agent in the office opens the menu link → lands on the link-creation page.
  • An outsider opens anketa.ekocentrs.lv/izveidot → does not get in.
  • A client link /aizpildit?d=… opens anonymously — in another browser, on a phone, with no VPN and no account.
  • A client fills the questionnaire in to the end and downloads the PDF.

When you are done

Three things from you:

  • the public deploy key from step 1 (or a note that you would rather have an archive);
  • confirmation that anketa.ekocentrs.lv exists and points where it should;
  • a short note on how exactly /izveidot is protected — so we know what to tell an agent the first time they try to get in.

If anything is unclear, or something in your infrastructure calls for a different approach, write to us and we will adapt.
